# Deploying FinFlow AI

Three free services, in this order — each step needs a value from the one before it:

| Piece | Service | Free tier |
|---|---|---|
| Database | MongoDB Atlas | M0 cluster, 512 MB, no card required |
| Backend | Render (Docker) | 750 hours/month, sleeps after 15 min idle |
| Frontend | Vercel | Hobby plan, unlimited static deploys |

The repository already contains `render.yaml` and `frontend/vercel.json`, so both
platforms configure themselves from the repo.

---

## 1. MongoDB Atlas

1. Create a free account at <https://www.mongodb.com/cloud/atlas/register>.
2. **Build a Database → M0 (Free)**. Pick the region nearest you (Mumbai `ap-south-1`
   if it is offered) and create the cluster.
3. **Database Access → Add New Database User.** Username `finflow`, and let Atlas
   autogenerate the password. Copy the password — it is shown only once.
4. **Network Access → Add IP Address → Allow access from anywhere (`0.0.0.0/0`).**
   Render's free plan has no fixed outbound IP, so a narrower rule would block it.
5. **Database → Connect → Drivers → Python** and copy the connection string. It
   looks like:

   ```
   mongodb+srv://finflow:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```

   Replace `<password>` with the real password. Keep this string — it is `MONGODB_URL`
   in the next step. Do not commit it anywhere.

The app creates its own collections and indexes on first start, so there is nothing
to import.

---

## 2. Backend on Render

1. Sign in at <https://dashboard.render.com> with GitHub.
2. **New → Blueprint**, pick the `Finflow` repository. Render reads `render.yaml`
   and proposes one service, `finflow-api`.
3. It will ask for the three values marked `sync: false`:

   | Variable | Value |
   |---|---|
   | `MONGODB_URL` | the Atlas connection string from step 1 |
   | `BACKEND_CORS_ORIGINS` | leave as `http://localhost:5173` for now; corrected in step 4 |
   | `GROQ_API_KEY` | your Groq key, or leave blank |

   `SECRET_KEY` is generated by Render. Leave it alone — regenerating it signs out
   every user.

4. **Apply.** The first build takes 3–5 minutes. When it finishes you get a URL such
   as `https://finflow-api.onrender.com`.
5. Check it:

   ```bash
   curl https://finflow-api.onrender.com/api/v1/health
   ```

   Expect `{"status":"ok","service":"finflow-ai-api"}`. Interactive API docs are at
   `/docs`.

**About `GROQ_API_KEY`:** without it the copilot still answers, using the
deterministic rule-based path instead of the LLM. Nothing else changes.

---

## 3. Frontend on Vercel

1. Sign in at <https://vercel.com> with GitHub, then **Add New → Project** and import
   `Finflow`.
2. Set **Root Directory** to `frontend`. Vercel picks up the rest from
   `frontend/vercel.json`.
3. Add one environment variable:

   | Variable | Value |
   |---|---|
   | `VITE_API_BASE_URL` | `https://finflow-api.onrender.com/api/v1` |

   The `/api/v1` suffix matters — without it every request 404s. This is read at
   build time, so changing it later needs a redeploy, not just a restart.
4. **Deploy.** You get a URL such as `https://finflow.vercel.app`.

---

## 4. Connect the two (do not skip)

The backend rejects browser requests from unknown origins, so it needs to be told
the Vercel URL:

1. Render → `finflow-api` → **Environment** → edit `BACKEND_CORS_ORIGINS` to your
   Vercel URL, with no trailing slash:

   ```
   https://finflow.vercel.app
   ```

   Several origins are comma-separated, e.g. to keep local development working:

   ```
   https://finflow.vercel.app,http://localhost:5173
   ```
2. Save. Render restarts the service automatically.

---

## 5. Verify

1. Open the Vercel URL and register an account. (The local accounts are in your
   local MongoDB, not Atlas — the deployed app starts empty.)
2. Import a CSV from `data/seed/` or `data/demo-upload/` on the Transactions page.
3. The dashboard should fill in, and monthly income should be derived from the
   salary credits in the file.

If something fails, check in this order:

| Symptom | Cause |
|---|---|
| "Could not reach the server" | Render service asleep — the first request takes ~50 s to wake it |
| Requests fail with a CORS error in the browser console | `BACKEND_CORS_ORIGINS` does not match the Vercel URL exactly |
| Every request 404s | `VITE_API_BASE_URL` is missing the `/api/v1` suffix |
| Backend logs "SECRET_KEY must be changed" | `APP_ENV=production` without a generated `SECRET_KEY` |
| Backend logs a server-selection timeout | Atlas IP allowlist is not `0.0.0.0/0`, or the password in the URL is wrong |

---

## Notes on the free tiers

- **Render sleeps after 15 minutes of inactivity.** The next request wakes it, which
  takes about 50 seconds. Worth knowing before a live demo — open the app a minute
  beforehand.
- **Atlas M0 is limited to 512 MB** and pauses after 60 days of no activity.
- Every push to `main` redeploys both services. CI runs first on GitHub Actions, but
  neither platform waits for it, so a red build still deploys.
